# Аналитические задачи на SQL

Три учебных кейса на SQLite: продажи, активация пользователей и обработка заявок. В репозитории находятся исходные CSV, схема таблиц, SQL-запросы и результаты расчётов. Python используется для загрузки данных и проверки результатов; аналитические расчёты написаны на SQL.

## Кейсы

| Кейс | Что рассчитывается | Решение |
|---|---|---|
| Интернет-магазин | Выручка, средний чек, продажи категорий, повторные покупки | [Задача и результаты](01-shop/README.md) · [SQL](01-shop/sql) |
| Активация | Последовательная воронка с окном 7 дней в разрезе каналов | [Задача и результаты](02-funnel/README.md) · [SQL](02-funnel/sql) |
| Обработка заявок | Время закрытия, SLA 24 часа, просроченный остаток | [Задача и результаты](03-service/README.md) · [SQL](03-service/sql) |

## Запуск

Нужен Python 3.9 или новее с модулем sqlite3. Дополнительные библиотеки не требуются.

```sh
python3 scripts/run.py
python3 tests/verify.py
```

Первая команда создаёт базы `project.sqlite` из CSV, выполняет файлы SQL и обновляет `results/`. Вторая независимо пересчитывает показатели на Python и сравнивает их с CSV-результатами. При успехе выводится `PASS`.

Один кейс:

```sh
python3 scripts/run.py --project 01-shop
```

После запуска отдельный запрос можно выполнить через SQLite CLI:

```sh
sqlite3 -header -column 01-shop/project.sqlite < 01-shop/sql/01_monthly.sql
```

Или открыть `project.sqlite` в имеющемся редакторе баз данных и выполнить содержимое нужного SQL-файла.

## Данные и определения

Данные синтетические, созданные для этих задач. Они не содержат реальных клиентов и не представляют работу для заказчика. В CSV первая строка содержит имена столбцов, пустое поле соответствует SQL NULL. Даты записаны в ISO-формате, деньги — в целых копейках.

Определения метрик, ограничения и результаты описаны в каждом кейсе. Различия между каналами и командами в синтетическом наборе не являются доказательством причинных эффектов.

## Проверка

- Проверяются ограничения схемы, целостность базы и внешние ключи.
- Выручка пересчитывается по исходным строкам и сверяется между разрезами.
- Воронка независимо пересчитывается с учётом порядка событий и семидневного окна.
- SLA и открытый остаток сверяются с исходными датами; закрытые и открытые заявки в сумме дают 150.

Проверки покрывают поставляемые наборы, но не все возможные граничные случаи. В данных воронки специально присутствуют повторные события и событие до регистрации.

## Структура

```text
01-shop/          # продажи
02-funnel/        # активация
03-service/       # обработка заявок
  data/           # исходные CSV
  sql/            # схема и отдельные запросы
  results/        # результаты запросов
scripts/run.py    # воспроизводимый запуск
tests/verify.py   # независимая проверка расчётов
```
